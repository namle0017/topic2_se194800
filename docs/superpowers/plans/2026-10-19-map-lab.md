# Flutter Map Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a runnable `map_lab` Flutter project that completes all three exercises: device location, OSRM driving route metrics, and foreground GPS tracking.

**Architecture:** Start from the supplied Map Demo reference at commit `8651d5a` so Questions 1 and 2 retain their tested domain/data/presentation separation. Add a focused foreground tracker around `GeolocatorPlatform`, expose tracking state through `BookingController`, and let the existing MapLibre widget render the newest device fix without replacing a manually selected pin. Route refreshes are throttled by both distance and time.

**Tech Stack:** Flutter, Dart 3.13, MapLibre GL, OpenFreeMap, Geolocator, Photon, OSRM, `http`, Flutter Test.

**Spec:** `docs/spec/Map_Practice_Huong_dan_thuc_hanh.docx`

## Global Constraints

- Preserve the target project's `map_lab` package identity and generated Android/iOS application IDs.
- Use MapLibre/OpenFreeMap for rendering, Photon for search/reverse geocoding, and OSRM for driving routes.
- OSRM coordinates are `longitude,latitude`; distance is metres and duration is seconds.
- Foreground tracking uses high accuracy and `distanceFilter = 10` metres.
- Reject fixes older than 30 seconds or more than 5 seconds in the future.
- Stop the subscription when tracking is disabled, the app leaves foreground, the screen is disposed, or the controller is disposed.
- A manual pin remains authoritative; tracking may update the separate device marker but must not overwrite that pin.
- Refresh routing only after at least 50 metres of movement and at least 10 seconds since the previous live refresh.
- ETA remains OSRM's estimate and must be labelled as not using live traffic.

## Review Focus

- Permission denied or location services disabled must yield a recoverable Vietnamese error without starting a stream.
- Stale, future, non-finite, or out-of-range fixes must not update controller or map state.
- A canceled/old subscription must not publish after restart, stop, or dispose.
- Rapid valid fixes must update the marker but not call OSRM on every event.
- Manual pickup/pin selection must survive live device movement.
